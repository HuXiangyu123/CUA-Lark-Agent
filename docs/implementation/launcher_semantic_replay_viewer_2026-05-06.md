# Launcher Semantic Replay Viewer

Date: 2026-05-06

## Status

Implementation plan for exposing semantic trace replay artifacts in the
launcher as a standalone viewer.

## Module Responsibility

The launcher should let users inspect semantic replay artifacts generated by
`S3RuntimeRecorder` and `ReportBuilder`:

- `semantic_trace.json`
- `replay_draft.md`
- associated `summary.json`

The viewer is a review surface only. It must not execute recorded actions,
compile a fixed workflow, or drive the Feishu desktop client.

## Boundaries

In scope:

- Add a separate launcher tab for semantic replay review.
- Discover completed run directories under `artifacts/test_runs`.
- Show run metadata and a text preview of `replay_draft.md`.
- Parse `semantic_trace.json` into a structured step timeline.
- Show per-step semantic details: page, visible controls, action summary,
  verification result, failure type, recovery marker, and timestamp.
- Show a run-level review summary with trace completeness, failed step count,
  recovery count, screenshot availability, page path, and warnings.
- Provide buttons to refresh the list and open the run directory or replay
  draft in the system shell.
- Provide a shortcut to open the screenshots directory when it exists.
- Provide a copy-to-clipboard action for the review summary.

Out of scope:

- No automatic replay.
- No script generation.
- No workflow or deterministic executor.
- No image extraction or screenshot annotation.
- No coordinate, `bbox`, confidence, or image-dimension display.

## Image Input Gate

No new screenshots are required for this feature.

The launcher only displays existing artifact files. If a future viewer needs
thumbnail previews or semantic validation of a screenshot, stop and ask for:

- screenshot file path or attached image
- product domain
- expected page type
- visible controls/text to validate

Do not ask for or store coordinates, bounding boxes, confidence scores, or
pixel measurements.

- Risk: no artifacts exist yet, so the tab could look broken.
  Mitigation: show an explicit empty-state message.

  generation.
  Mitigation: discover any recognized read-only run artifact and mark missing
  semantic trace or replay draft as review warnings.

  Mitigation: disable listbox selection export and keep an explicit selected
  run index.

  Mitigation: button labels and code paths only open files/directories.

  unaffected.

## Compatibility Fix Plan

Issue:

- Previous Feishu run records can exist without `semantic_trace.json` or
  `replay_draft.md`, so strict semantic-only discovery hides valid run
  directories.
- Toolbar buttons can report "no directory" after focus leaves the run list.

Implementation:

- Treat `summary.json`, `report.md`, `actions.jsonl`, `screenshots/`,
  `semantic_trace.json`, and `replay_draft.md` as recognized run artifacts.
- Keep semantic replay as the preferred preview. If it is missing, preview
  `report.md` as a legacy read-only report and keep warnings visible.
- Preserve the selected run independently of widget focus.
- Keep all behavior read-only; no replay executor or fixed workflow is added.
